# Diaries

**Diaries** — приложение на Python и Flask для создания, заполнения и ведения медицинских дневников.

Проект ориентирован на медицинских работников, в частности врачей отделений реанимации и интенсивной терапии (ОРИТ). Основная цель — сокращение времени на оформление медицинской документации с помощью настраиваемых шаблонов, справочников, автоматизированной обработки результатов исследований и искусственного интеллекта.

Приложение поддерживает запуск в веб-режиме и в виде локального настольного приложения для Windows.

## Возможности

### Управление пользователями

- Регистрация, авторизация и редактирование личного профиля.
- Разграничение прав пользователей, администраторов и суперадминистраторов.
- Индивидуальное хранение медицинских дневников.

### Медицинские дневники

- Создание, заполнение, редактирование, просмотр и удаление дневников.
- Автоматическая нумерация дневников.
- Формирование записей по категориям и сохранение введённых данных.
- Автоматическая генерация итогового текста, включая диагноз, план интенсивной терапии и подпись врача.

### Шаблоны медицинских записей

- Создание категорий, текстовых шаблонов, переменных и вариантов заполнения.
- Поддержка текстовых, числовых полей, дат, одиночного и множественного выбора.
- Изменение последовательности выбранных значений.
- Автоматическая подстановка данных в шаблоны.

### План интенсивной терапии

- Ведение справочников целей терапии и лекарственных препаратов.
- Настройка справочников режимов, диет, единиц измерения, способов введения и кратности назначений.
- Формирование плана инфузионной терапии.
- Добавление отдельных и совместных назначений лекарственных препаратов.
- Указание дозировки, способа введения, кратности и даты начала терапии.
- Отдельная логика формирования антибактериальной и анальгетической терапии.
- Автоматическое формирование текстового плана интенсивной терапии.

### Лабораторные исследования

- Обработка текстовых результатов лабораторных исследований.
- Распознавание показателей и дат исследований.
- Формирование динамики лабораторных показателей.
- Группировка результатов по категориям.
- Настройка справочников показателей, источников и альтернативных наименований (алиасов).
- Настройка точности округления числовых значений.
- Обработка бактериологических исследований и группировка антибиотиков по категориям чувствительности S, I и R.

Поддерживаемые исследования:

- Общий анализ крови, включая ручную лейкоцитарную формулу.
- Коагулограмма.
- Биохимический анализ крови.
- Бактериологические исследования крови на стерильность.

### ИИ-интерпретация лабораторных исследований

В приложение интегрирован модуль интерпретации лабораторных исследований с использованием Google Gemini API.

- Анализ предварительно обработанных лабораторных показателей.
- Выявление клинически значимых отклонений.
- Оценка динамики показателей.
- Выделение лабораторных синдромов и оценка взаимосвязанных показателей.
- Формирование кратких клинико-лабораторных заключений на русском языке.
- Раздельный анализ категорий лабораторных исследований.
- Параллельная обработка категорий для сокращения времени ожидания.
- Получение заключения без перезагрузки страницы.

ИИ получает подготовленные лабораторным модулем данные. Заключение носит вспомогательный характер и не заменяет клиническую оценку врача. Модуль не предназначен для самостоятельной постановки диагнозов или назначения лечения.

ИИ-интерпретация является дополнительной функцией. Основные возможности приложения доступны без API-ключа и подключения к интернету.

### Инструментальные исследования

- Обработка текстовых результатов инструментальных исследований.
- Определение вида и даты исследования, извлечение заключений.
- Группировка результатов по видам исследований и датам.
- Настройка справочников исследований, источников и алиасов.
- Автоматическое формирование текстового блока инструментальных исследований.

### Административная панель

- Управление пользователями и правами доступа.
- Управление категориями, шаблонами и переменными.
- Управление справочниками терапии, лабораторных и инструментальных исследований.

## Важная информация

> [!IMPORTANT]
> Модули обработки лабораторных и инструментальных исследований ориентированы на текстовые данные из медицинской информационной системы **КМИС**. Корректная обработка данных из других систем не гарантируется.
>
> Все автоматически сформированные записи, включая заключения ИИ, требуют обязательной проверки медицинским работником.

При использовании Gemini данные передаются внешнему сервису Google. Не передавайте персональные данные пациентов, включая ФИО, ИИН, номера медицинских карт и другие идентификаторы. Используйте только надлежащим образом обезличенные данные при наличии разрешения организации и соблюдении применимых требований медицинской конфиденциальности. Само наличие парсера не гарантирует полного обезличивания.

## Технологии

- **Backend:** Python, Flask, Flask-SQLAlchemy, SQLAlchemy, Flask-Migrate, Alembic, Flask-Login, Flask-WTF, Flask-Admin, Jinja2, python-dotenv.

- **База данных:** SQLite.
- **Искусственный интеллект:** Google Gemini API.
- **Тестирование и качество кода:** Pytest, Ruff.
- **Настольная версия:** Waitress, PyInstaller, Inno Setup.

## Установка и запуск из исходного кода

### 1. Клонирование репозитория

```bash
git clone https://github.com/sashkaryzhik1908-netizen/diaries_app.git
cd diaries_app
```

### 2. Создание виртуального окружения

```bash
python -m venv venv
```

Активация в Windows (CMD):

```bat
venv\Scripts\activate
```

В PowerShell:

```powershell
.\venv\Scripts\Activate.ps1
```

В Git Bash:

```bash
source venv/Scripts/activate
```

В Linux или macOS:

```bash
source venv/bin/activate
```

### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 4. Настройка переменных окружения

Создайте файл `.env` в корне проекта на основе `.env.example`.

Сгенерируйте секретный ключ:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

Пример содержимого `.env`:

```env
SECRET_KEY=your-generated-secret-key
FLASK_DEBUG=false
GEMINI_API_KEY=
```

Переменная `GEMINI_API_KEY` может оставаться пустой, если ИИ-интерпретация не используется. Не публикуйте `.env` и не передавайте секретные ключи другим пользователям.

### 5. Подготовка базы данных

В репозитории предусмотрена начальная база SQLite с предварительно заполненными справочниками и шаблонами.

```bash
flask --app run db upgrade
```

### 6. Запуск приложения

```bash
python run.py
```

Приложение будет доступно по адресу: http://127.0.0.1:5000

## Подключение искусственного интеллекта (Google Gemini)

Для использования ИИ-интерпретации необходимы аккаунт Google, действующий API-ключ Gemini и подключение к интернету. Доступность моделей, квоты и стоимость запросов зависят от условий Google и настроек проекта.

### 1. Получение API-ключа

1. Откройте [Google AI Studio](https://aistudio.google.com/).
2. Авторизуйтесь в аккаунте Google.
3. Перейдите на [страницу API-ключей](https://aistudio.google.com/apikey).
4. Выберите создание API-ключа (Create API key).
5. При необходимости выберите или создайте проект Google Cloud.
6. Скопируйте полученный ключ.

### 2. Настройка API-ключа при запуске из исходного кода

Откройте файл `.env` в корне проекта и заполните переменную:

```env
GEMINI_API_KEY=your-gemini-api-key
```

Замените `your-gemini-api-key` собственным ключом. Остальные настройки `.env` оставьте без изменений.

Перезапустите приложение:

```bash
python run.py
```

### 3. Настройка API-ключа для настольной версии Windows

Можно задать ключ как пользовательскую переменную окружения Windows, если установленная сборка считывает `GEMINI_API_KEY` из окружения процесса.

1. Откройте меню «Пуск» и найдите «Изменение переменных среды для текущего пользователя».
2. В разделе пользовательских переменных нажмите «Создать».
3. В поле имени укажите `GEMINI_API_KEY`.
4. В поле значения вставьте полученный API-ключ.
5. Сохраните изменения и полностью перезапустите Diaries. При необходимости выйдите из учётной записи Windows и войдите снова.

Не добавляйте личный API-ключ в исходный код, установщик или распространяемую сборку приложения.

### 4. Использование ИИ-интерпретации

1. Откройте медицинский дневник.
2. Перейдите в раздел лабораторных исследований.
3. Вставьте обезличенный текст результатов исследований из КМИС.
4. Выполните обработку лабораторных данных и запустите ИИ-анализ.
5. Дождитесь формирования заключений.
6. Проверьте заключения перед использованием в медицинской документации.

### 5. Возможные ошибки

| Ошибка | Возможная причина и решение |
| --- | --- |
| API-ключ отсутствует | Проверьте переменную `GEMINI_API_KEY` и перезапустите приложение. |
| 400 / 401 / 403 | Проверьте корректность ключа, права доступа и ограничения проекта Google Cloud. |
| 404 | Настроенная модель недоступна. Проверьте доступные модели и настройку `AI_MODEL` в `laboratory/ai_service.py`. |
| 429 | Превышена квота или частота запросов. Проверьте лимиты проекта. |
| 502 / ошибка формирования заключения | Проверьте подключение к интернету и журнал ошибок приложения. |

Актуальная документация: [Gemini API](https://ai.google.dev/gemini-api/docs), [API-ключи](https://ai.google.dev/gemini-api/docs/api-key), [тарифы](https://ai.google.dev/gemini-api/docs/pricing).

## Настольная версия для Windows

Настольная версия позволяет использовать Diaries без отдельной установки Python и зависимостей. Основные функции доступны без интернета; для ИИ-интерпретации требуется подключение к Gemini API.

### Сборка исполняемого файла

```bash
pip install pyinstaller
pyinstaller --clean --noconfirm desktop.spec
```

Результат сборки:

```text
dist/Diaries/Diaries.exe
```

Для корректной работы необходимо сохранять весь каталог `dist/Diaries`, а не только исполняемый файл.

### Создание установщика

Для создания установщика используется Inno Setup. Откройте скрипт сборки установщика `.iss`, убедитесь, что он использует актуальный каталог `dist/Diaries`, и выполните компиляцию.

Установщик предназначен для установки, обновления и удаления приложения, а также создания ярлыков.

### Хранение пользовательских данных

База данных настольной версии хранится отдельно от файлов приложения:

```text
%APPDATA%\Diaries\database.db
```

Перед обновлением рекомендуется создать резервную копию базы данных. Раздельное хранение предназначено для сохранения пользовательских данных при обновлении приложения.

## База данных

В проекте используется SQLite. Взаимодействие с базой данных осуществляется через SQLAlchemy ORM, управление изменениями структуры — через Flask-Migrate и Alembic.

После клонирования репозитория пользователь получает локальную копию начальной базы. Изменения в ней не влияют на исходную базу в GitHub.

Создание миграции при изменении моделей:

```bash
flask --app run db migrate -m "Description of changes"
```

Применение миграций:

```bash
flask --app run db upgrade
```

Для резервного копирования сохраните копию `database.db` при полностью остановленном приложении. Не публикуйте базы с реальными медицинскими записями или персональными данными пациентов.

## Архитектура проекта

Приложение имеет модульную архитектуру с разделением ответственности между компонентами:

- **Models** — модели базы данных и связи между ними.
- **Routes** — обработка HTTP-запросов.
- **Services** — бизнес-логика.
- **Forms** — формы и валидация данных.
- **Templates** — пользовательский интерфейс.
- **Parsers** — обработка исходных текстовых данных исследований.
- **AI Service** — взаимодействие с Gemini API и формирование заключений.
- **Tests** — автоматизированное тестирование.

Для организации маршрутов используются Flask Blueprints, для создания приложения — паттерн Application Factory.
